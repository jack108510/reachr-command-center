# Wildrose Outreach Dashboard

Public, privacy-safe dashboard showing aggregate Messenger outreach totals. It intentionally excludes prospect names, source evidence, message content, and local paths.

The signed-in workspace includes Overview, Contacts / CRM and inbox, Outreach operations, and Meta analytics. Outreach operations and Meta analytics read the private local Reachr server using the existing Supabase session for owner authentication; the Graph API token stays on that server and is never published in this GitHub Pages repository. Meta currently provides ad account totals, campaign delivery, Page audience, recent posts, and share counts; reaction, comment, and post-view metrics are unavailable to this token. The operations view shows confirmed sends, sender blockers, verified replies, and Page posting status; actual Messenger sending still requires the owning account to pass its identity checks. Wildrose branding uses the logo hosted by `wildroseautomations.ca`.

The Messenger hub is the default workspace. It puts replies waiting, needs action, and interested conversations at the top, with quick filters and search across business, person, reply preview, and private note. Opening a conversation shows stored thread history, a reply workspace, private status, and notes. The reply workspace always lets the operator compose and copy an exact message for manual delivery in Messenger; copying is never counted as sending. Direct sending appears only when the owning sender passes the server's verification checks. Sending requires a separate confirmation, and the server rechecks sender, recipient, and verified inbound evidence before Messenger delivery. The live Messenger link provides complete context. If the backend cannot be reached, the hub switches to a read-only Supabase archive; no live send or follow-up controls are shown. Drafts saved in the older Supabase inbox remain unsent; a queued draft is not evidence of delivery.

The Publish to Page tab embeds the Wildrose Facebook Page composer in this site. It supports text and up to four JPG/PNG photos, a live preview, immediate publishing, or scheduling 10 minutes to 30 days ahead. A separate confirmation shows the selected local date and time. Scheduled posts are submitted to Meta itself, then listed from Meta with a cancel action. It calls the private `rose-page-publisher` service at `wildrose-widget.wildeautomations.com/api/command-center` with the current Supabase access token; that server validates the owner and holds the Page token. The service runs on the Rose production VM. The owner connects a Facebook Page access token once from the Command Center. The VM needs to be online to create, review, or cancel posts; Meta itself publishes accepted scheduled posts at the selected time. This does not publish to personal profiles, Groups, or ads.

This is not yet a complete mirror of each personal Facebook sender inbox. The server records outreach conversations, and the Supabase archive is a partial historical snapshot. Meta's official Messenger Conversations API covers Facebook Page conversations; personal sender inboxes need a separate, verified sync on the sender machine. The hub labels this coverage so archived or missing chats are not presented as a complete inbox.

## Supabase inbox

The private Messenger archive reads `reachr_conversations` and `reachr_messages` through the signed-in user's RLS permissions. It lists all stored outreach conversations, including those without a stored inbound reply, with sender and activity filters; opening one shows all stored inbound and outbound messages in order. The operator can compose and queue an exact reply in `reachr_reply_jobs` with status `draft`, then see the saved item in that conversation. Queueing does not approve, deliver, or add it to sent messages. The Script Library reads and manages reusable templates in `reachr_script_templates`. The first acquisition script asks about a specific observed promotion, area, and schedule; placeholders must be filled before queuing. Templates can be created, edited, archived, and loaded into the Messenger composer. The existing RLS policies limit drafts and scripts to the signed-in operator, and reply approval remains unavailable to browser roles. The inbox refreshes manually and every minute while visible. The Overview leads with stored replies and also tracks total outreach as the all-time count of stored outbound messages from `reachr_dashboard_summary()`. Its 14-day chart shows inbound activity. Contacts / CRM reads `reachr_contacts` and `reachr_contact_events` in Supabase. Apply the three migrations in filename order before importing. A September 2026 backfill used the private, evidence-backed ledger and partial Messenger-rendered archive, excluding Marketplace. The local verified CRM was separately migrated with its audit events. These are partial historical snapshots, not complete Messenger history or an automatic sync. Operators can open the exact live Messenger thread for current context.

### VM Page connection

The Command Center publisher API is served by `rose-page-publisher.service` on the Rose production VM. Caddy sends only `/api/command-center/*` on `wildrose-widget.wildeautomations.com` to its loopback port 8847; the existing Rose backend keeps the rest of the hostname. The owner signs in to the Command Center, opens **Publish to Page**, and enters a Facebook **Page access token**. `POST /api/command-center/connect` checks Meta's `/me` identity and scheduled-post access, then stores the token in `/var/lib/rose-page-publisher/connection.json` (directory mode 0700, file mode 0600). The token is not returned to the browser. This connection replaces the old Mac as the Command Center's publishing path. A Meta app API key alone cannot publish; the operator must obtain a Page token with Page posting permissions. No post is sent by connecting. Once Meta accepts a scheduled post, Meta handles the later publication independently of this VM.

The Organic content tab reads fresh Page counts and recent posts from the same VM publisher after the owner connects the Page. It no longer depends on the offline n8n tunnel. Paid ad metrics remain outside this Page report. When the live Messenger sender server is unavailable, the Messenger tab switches to the Supabase stored archive, labels that mode, and disables live sending.

The Organic content tab now shows per-post reactions, comments, shares, and a simple interaction total for the ten most recent posts. Meta may withhold reaction or comment totals for some Page tokens; missing values display as a dash, and the report falls back to posts and shares if the richer Graph query is rejected. The interaction total is an arithmetic sum, not unique engaged people or reach.
