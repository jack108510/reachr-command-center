# Wildrose Outreach Dashboard

Public, privacy-safe dashboard showing aggregate Messenger outreach totals. It intentionally excludes prospect names, source evidence, message content, and local paths.

The signed-in workspace includes Overview, Contacts / CRM and inbox, Outreach operations, and Meta analytics. Outreach operations and Meta analytics read the private local Reachr server using the existing Supabase session for owner authentication; the Graph API token stays on that server and is never published in this GitHub Pages repository. Meta currently provides ad account totals, campaign delivery, Page audience, recent posts, and share counts; reaction, comment, and post-view metrics are unavailable to this token. The operations view shows confirmed sends, sender blockers, verified replies, and Page posting status; actual Messenger sending still requires the owning account to pass its identity checks. Wildrose branding uses the logo hosted by `wildroseautomations.ca`.

The Messenger hub is the default workspace. It lists all conversations recorded by the outreach server, with search, sender-account and status filters, verified replies first, and access to stored thread history, private status, notes, and a reply composer when the owning sender passes the server's verification checks. Saving status or notes updates the private Command Center; sending requires a separate confirmation and the server rechecks sender, recipient, and verified inbound evidence before Messenger delivery. It links to Messenger for complete context. If the live backend cannot be reached, the hub clearly switches to a read-only Supabase archive; no live send or follow-up controls are shown. Drafts saved in the older Supabase inbox remain unsent; a queued draft is not evidence of delivery.

This is not yet a complete mirror of each personal Facebook sender inbox. The server records outreach conversations, and the Supabase archive is a partial historical snapshot. Meta's official Messenger Conversations API covers Facebook Page conversations; personal sender inboxes need a separate, verified sync on the sender machine. The hub labels this coverage so archived or missing chats are not presented as a complete inbox.

## Supabase inbox

The private Messenger archive reads `reachr_conversations` and `reachr_messages` through the signed-in user's RLS permissions. It lists all stored outreach conversations, including those without a stored inbound reply, with sender and activity filters; opening one shows all stored inbound and outbound messages in order. The operator can compose and queue an exact reply in `reachr_reply_jobs` with status `draft`, then see the saved item in that conversation. Queueing does not approve, deliver, or add it to sent messages. The Script Library reads and manages reusable templates in `reachr_script_templates`. The first acquisition script asks about a specific observed promotion, area, and schedule; placeholders must be filled before queuing. Templates can be created, edited, archived, and loaded into the Messenger composer. The existing RLS policies limit drafts and scripts to the signed-in operator, and reply approval remains unavailable to browser roles. The inbox refreshes manually and every minute while visible. The Overview leads with stored replies and also tracks total outreach as the all-time count of stored outbound messages from `reachr_dashboard_summary()`. Its 14-day chart shows inbound activity. Contacts / CRM reads `reachr_contacts` and `reachr_contact_events` in Supabase. Apply the three migrations in filename order before importing. A September 2026 backfill used the private, evidence-backed ledger and partial Messenger-rendered archive, excluding Marketplace. The local verified CRM was separately migrated with its audit events. These are partial historical snapshots, not complete Messenger history or an automatic sync. Operators can open the exact live Messenger thread for current context.
