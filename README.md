# Wildrose Outreach Dashboard

Public, privacy-safe dashboard showing aggregate Messenger outreach totals. It intentionally excludes prospect names, source evidence, message content, and local paths.

The signed-in workspace includes Overview, Contacts / CRM and inbox, Outreach operations, and Meta analytics. Outreach operations and Meta analytics read the private local Reachr server using the existing Supabase session for owner authentication; the Graph API token stays on that server and is never published in this GitHub Pages repository. Meta currently provides ad account totals, campaign delivery, Page audience, recent posts, and share counts; reaction, comment, and post-view metrics are unavailable to this token. The operations view shows confirmed sends, sender blockers, verified replies, and Page posting status; actual Messenger sending still requires the owning account to pass its identity checks. Wildrose branding uses the logo hosted by `wildroseautomations.ca`.

The Client communications tab prioritizes verified replies and conversations needing review, with search and filters for follow-up. Opening a conversation shows its stored history, private management status and note, and a reply composer when the owning sender passes the server's verification checks. Saving status or notes updates the private Command Center; sending requires a separate confirmation and the server rechecks sender, recipient, and verified inbound evidence before Messenger delivery. The tab links to Messenger for complete context and keeps the private Command Center as a fallback. It hides stale client data if its live backend cannot be reached. Drafts saved in the older Supabase inbox remain unsent; a queued draft is not evidence of delivery.

## Supabase inbox

The private Messenger view reads `reachr_conversations` and `reachr_messages` through the signed-in user's RLS permissions. Its inbox lists only conversations with a stored inbound reply; opening one shows all stored inbound and outbound messages in order. The operator can compose and queue an exact reply in `reachr_reply_jobs` with status `draft`, then see the saved item in that conversation. Queueing does not approve, deliver, or add it to sent messages. The Script Library reads and manages reusable templates in `reachr_script_templates`. The first acquisition script asks about a specific observed promotion, area, and schedule; placeholders must be filled before queuing. Templates can be created, edited, archived, and loaded into the Messenger composer. The existing RLS policies limit drafts and scripts to the signed-in operator, and reply approval remains unavailable to browser roles. The inbox refreshes manually and every minute while visible. The Overview leads with stored replies and also tracks total outreach as the all-time count of stored outbound messages from `reachr_dashboard_summary()`. Its 14-day chart shows inbound activity. Contacts / CRM reads `reachr_contacts` and `reachr_contact_events` in Supabase. Apply the three migrations in filename order before importing. A September 2026 backfill used the private, evidence-backed ledger and partial Messenger-rendered archive, excluding Marketplace. The local verified CRM was separately migrated with its audit events. These are partial historical snapshots, not complete Messenger history or an automatic sync. Operators can open the exact live Messenger thread for current context.
